# Balance Waste — ระบบบริหารจัดการของเสีย (Waste Management)

**บริษัท แน็ป นิวตริซายส์ (ประเทศไทย) จำกัด** · ทะเบียนโรงงาน 82260007625693 · หนังสืออนุญาต สก.2 เลขที่ 2569-8409 (ปี 2569)

ใช้ลงข้อมูลปริมาณของเสียที่จัดเก็บในโรงงาน: เลือกประเภทของเสีย กรอกน้ำหนัก (**ตัน**) และภาชนะบรรจุ (ถัง 200 ลิตร / IBC / Bigbag)
แล้วติดตามยอดคงเหลือ การส่งกำจัด และการใช้โควตาตามปริมาณที่ได้รับอนุญาต

- รีโป: https://github.com/watanathep8-dotcom/balance-waste-nap
- หน้าเว็บ: GitHub Pages จากโฟลเดอร์ `docs/` → https://watanathep8-dotcom.github.io/balance-waste-nap/
- Backend: Google Apps Script (`apps-script/Code.gs` ไฟล์เดียว) เก็บข้อมูลใน Google Sheets

## ความสามารถ

| หน้า | รายละเอียด |
|---|---|
| แดชบอร์ด | KPI (คงเหลือรวม, จัดเก็บเดือนนี้, ส่งกำจัดปีนี้, % โควตา), เกจเข็มโควตารวม, วงแหวนโควตาแยกประเภท, กราฟ 12 เดือน, โดนัทภาชนะ, โควตาตามผู้รับ, แจ้งเตือน, รายการล่าสุด |
| บันทึกจัดเก็บ | เลือกประเภท (ค้นหาได้ แยกตามผู้รับ) · น้ำหนัก **ตัน** (ทศนิยม 3 ตำแหน่ง = 1 กก. เช่น 0.125) ปุ่มลัด +0.1 / +0.5 / +1 / +5 / +10 ตัน · ภาชนะ + จำนวน · สถานที่จัดเก็บ · หมายเหตุ · โหมด **ยอดยกมา** สำหรับของที่มีอยู่ก่อนเริ่มใช้ระบบ |
| ส่งกำจัด / นำออก | แสดงยอดคงเหลือสด · ส่งเกินยอดคงเหลือ/จำนวนภาชนะไม่ได้ · เลขที่ใบกำกับการขนส่ง · ทะเบียนรถ |
| ข้อมูลภายใน (เฉพาะผู้ดูแลระบบ) | รายการที่จัดการภายในโรงงานเอง — ตัดยอดคงเหลือเหมือนส่งกำจัด แต่ **ไม่นับโควตา สก.2** · เมนู ยอดรวม กราฟ และรายการในประวัติ/Excel ส่งให้เฉพาะเซสชันผู้ดูแลระบบ (ซ่อนบนหน้าจอได้ด้วยไอคอนกุญแจท้ายหน้า) |
| คงเหลือ & โควตา | คงเหลือ = รับเข้า − ส่งกำจัด, ภาชนะในคลัง, % โควตาปีนี้ (เตือน ≥ 80 %, เกิน > 100 %), อายุล็อตเก่าสุด (FIFO, เตือนเกิน 90 วัน), สรุปตามผู้รับ |
| ประวัติรายการ | ตัวกรอง (ประเภท, รายการ, ช่วงวันที่, ผู้รับ, ค้นหา), ส่งออก Excel (CSV UTF-8 BOM, น้ำหนักเป็นตัน), แก้ไข / ลบ (ผู้ดูแลระบบ) |
| บันทึกประวัติ (Log) | ทุกการกระทำ ใคร ทำอะไร เมื่อไร (ผู้ดูแลระบบ) |
| ตั้งค่าประเภทของเสีย | แก้ไข / เพิ่มประเภท (รหัส, ชื่อ, ปริมาณอนุญาต (ตัน), รหัสการจัดการ, ผู้รับ, เปิด/ปิดใช้งาน) และปุ่มรีเซ็ตข้อมูล (ผู้ดูแลระบบ + ใส่รหัสผ่านอีกครั้ง) |

### สิทธิ์การใช้งาน (เข้าสู่ระบบด้วยรหัสผ่าน)

| ระดับ | Script Property | ทำอะไรได้ |
|---|---|---|
| เข้าดูได้อย่างเดียว | `WASTE_VIEW_PASSWORD` | ดูแดชบอร์ด คงเหลือ & โควตา ประวัติรายการ ส่งออก Excel |
| พนักงานกรอกข้อมูล | `WASTE_STAFF_PASSWORD` | ทุกอย่างของระดับดู + บันทึกจัดเก็บ / ยอดยกมา / ส่งกำจัด |
| ผู้ดูแลระบบ | `WASTE_RESET_PASSWORD` | ทุกอย่าง: แก้ไข / ลบรายการ, ตั้งค่าประเภทของเสีย, บันทึกประวัติ (Log), รีเซ็ตข้อมูล, ข้อมูลภายใน |

- เปิดเว็บแล้วจะเจอหน้าเข้าสู่ระบบ — รหัสผ่านที่ใส่เป็นตัวกำหนดระดับ (ถ้าตั้งรหัสเดียวกันสองระดับ จะได้ระดับที่สูงกว่า — ควรตั้งให้ต่างกัน)
- เซิร์ฟเวอร์ตรวจสิทธิ์ **ทุกคำสั่ง** (หน้าเว็บแค่ซ่อนปุ่ม/เมนูที่ใช้ไม่ได้) · เซสชันอยู่ได้ 12 ชั่วโมง หรือจนกดออกจากระบบ / ปิดแท็บ · เปลี่ยนรหัสผ่านระดับใด เซสชันของระดับนั้นจะหลุดทันที
- ใส่รหัสผิด: หน่วง 1 วินาทีต่อครั้ง · ผิด 5 ครั้งต่อเบราว์เซอร์ หรือ 30 ครั้งรวมทุกคน ภายใน 15 นาที → ล็อกการเข้าสู่ระบบ 15 นาที (ผู้ที่เข้าระบบอยู่แล้วใช้งานต่อได้)
- **ถ้า Property ใดยังไม่ได้ตั้ง ระดับนั้นจะเข้าสู่ระบบไม่ได้** (`setupSystem()` แจ้งใน log ว่ายังขาดตัวไหน)
- ต้องตั้ง **ชื่อผู้ใช้งานที่มุมขวาบน** ก่อนบันทึก — ชื่อถูกบันทึกเป็น “ผู้บันทึก” ทุกรายการ
- หน่วย: หน้าเว็บกรอกและแสดงผลเป็น **ตัน** (ทศนิยม 3 ตำแหน่ง ใส่คอมมาคั่นหลักพัน) แต่ชีตยังเก็บเป็น **กก.** เหมือนเดิม (`weight_kg`) — เซิร์ฟเวอร์แปลง ตัน → กก. แบบตรงตัว (0.125 ตัน = 125 กก.) ข้อมูลเดิมที่มีเศษ กก. (เช่น 1,234.56 กก.) จะแสดงเป็น 1.23456 ตัน ไม่ปัดทิ้ง
- ข้อมูลภายใน: ทุกรายการยังบันทึกในชีต `movements` (kind `treat`, เลขที่ `TR-…`, คอลัมน์ `method`) และ Log เสมอ — ผู้ที่ไม่ใช่ผู้ดูแลระบบจะไม่ได้รับรายละเอียดเลย ยอดคงเหลือที่แสดงเป็นยอดจริงเสมอ (รับเข้า − ส่งกำจัด − ข้อมูลภายใน)
- เซิร์ฟเวอร์ตรวจยอดย้อนหลังทุกครั้ง (ส่งกำจัด / แก้ไข / ลบ): น้ำหนักของทุกประเภท และจำนวนภาชนะแต่ละชนิด ต้องไม่ติดลบ ณ เวลาใดเลย
- ประเภทของเสีย 13 รายการตามหนังสืออนุญาต ปี 2569 (รวม 194 ตัน) ถูกสร้างอัตโนมัติตอน `setupSystem()` — รหัสเดียวกันที่ผู้รับต่างกันเป็นคนละรายการ
- ระบบ **ไม่สร้างยอดคงเหลือให้เอง** — ของเสียที่จัดเก็บอยู่ก่อนแล้ว (เช่น น้ำล้างเครื่องจักร, ตะกอนบำบัดน้ำเสีย) ให้บันทึกเป็น “ยอดยกมา” ตามที่ตรวจนับจริง

## ติดตั้ง (ครั้งแรก)

1. สร้างโปรเจกต์ใหม่ที่ https://script.google.com ตั้งชื่อโปรเจกต์ **Balance Waste Nap** แล้ววางเนื้อหา `apps-script/Code.gs`
   (และตั้งค่า `appsscript.json` ตามไฟล์ในรีโป: เขตเวลา Asia/Bangkok, V8)
2. **Project Settings → Script properties** เพิ่ม (ตั้งเอง ห้ามใส่ในโค้ด · ทั้ง 3 ค่าต้องไม่ซ้ำกัน):

   | Property | ค่า |
   |---|---|
   | `WASTE_VIEW_PASSWORD` | รหัสผ่านระดับ “เข้าดูได้อย่างเดียว” |
   | `WASTE_STAFF_PASSWORD` | รหัสผ่านระดับ “พนักงานกรอกข้อมูล” |
   | `WASTE_RESET_PASSWORD` | รหัสผ่านระดับ “ผู้ดูแลระบบ” (ใช้ยืนยันการรีเซ็ตข้อมูลด้วย) |

   `WASTE_SPREADSHEET_ID` ถูกสร้างให้อัตโนมัติโดย `setupSystem()` (ไม่ต้องตั้งเอง)
3. ในตัวแก้ไข Apps Script เลือกฟังก์ชันแล้วกด **Run**:
   - `setupSystem` — สร้างสเปรดชีต “Balance Waste Database” (ชีต `waste_types`, `movements`, `audit_logs`), ใส่ประเภทของเสีย 13 รายการ และบันทึก ID ไว้ใน Script Properties (รันซ้ำได้ ไม่สร้างซ้ำ)
   - `installKeepWarmTrigger` — (แนะนำ) ตั้ง trigger ทุก 10 นาที ให้ `keepWarm()` อุ่นแคชการอ่าน หน้าเว็บจะเปิดเร็วขึ้น
4. **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
5. คัดลอก URL ที่ลงท้ายด้วย `/exec` ใส่ใน `docs/config.js`:

   ```js
   window.WASTE_CONFIG = { apiUrl: "https://script.google.com/macros/s/XXXX/exec" };
   ```
6. เปิด GitHub Pages ของรีโป `watanathep8-dotcom/balance-waste-nap`: Settings → Pages → Branch `main` / folder `/docs`
   → https://watanathep8-dotcom.github.io/balance-waste-nap/

ฟังก์ชันอื่นที่รันจากตัวแก้ไขได้: `clearReadCache()` (หลังแก้สเปรดชีตด้วยมือ), `removeKeepWarmTrigger()`

## ทดสอบ / ดูตัวอย่างในเครื่อง

```bash
node test/gas-mock.js                    # ทดสอบ backend + frontend ทั้งหมด (ไม่ต่อ Google)
node test/dev-server.js 8777             # เปิด http://127.0.0.1:8777/ ด้วย Apps Script จำลองในหน่วยความจำ
node test/dev-server.js 8777 --demo      # เหมือนข้างบน + ข้อมูลตัวอย่าง (สร้างขึ้นเพื่อดูหน้าจอเท่านั้น ไม่ใช่ข้อมูลจริง)
```

dev-server ใช้รหัสผ่านจำลองเฉพาะในเครื่อง: `dev-view` / `dev-staff` / `dev-reset` (ไม่ใช่รหัสจริง)

## โครงสร้าง

```
apps-script/Code.gs      backend (doGet/doPost, LockService, CacheService, setupSystem, keepWarm)
appsscript.json          manifest
docs/index.html          หน้าเว็บ
docs/assets/app.js       frontend
docs/assets/style.css    ธีม (emerald / teal + amber), เอฟเฟกต์หมุนไอคอน, รองรับ prefers-reduced-motion
docs/config.js           apiUrl
test/gas-mock.js         mock ของ Apps Script + ชุดทดสอบ
test/dev-server.js       เซิร์ฟเวอร์ดูตัวอย่างในเครื่อง
```

API: ทุกคำสั่งเป็น `POST` แบบ `text/plain` (JSON `{action, token, …}`) — ไม่เกิด CORS preflight และ token ไม่อยู่ใน URL · `login` / `logout` ไม่ต้องใช้ token · `keepWarm()` (trigger) อ่านข้อมูลโดยตรง ไม่ผ่านเว็บ
